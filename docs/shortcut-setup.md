# iOS 단축어 연동 (Phase 0 입력 경로)

음성/텍스트로 말하거나 적으면 → 서버로 POST → 원문 저장 + 백그라운드 파싱.
아이폰/애플워치의 **단축어(Shortcuts)** 앱만으로 만든다. 앱 설치 없음.

만들 단축어는 3개다:

- **A. 음성 기록** — 받아쓰기 → 확인 → 전송 (§2)
- **B. 텍스트 기록** — 타이핑 → 전송 (§3)
- **C. 오늘 기록 확인** — 그날 원문 목록 보기 (§4, 임시 확인용)

---

## 0. 미리 준비할 값

| 이름               | 설명                                                    |
| ------------------ | ------------------------------------------------------- |
| `{{DEPLOY_URL}}`   | **배포된 서버 주소** (예: `https://health.example.com`) |
| `{{INGEST_TOKEN}}` | 서버의 `INGEST_TOKEN` 환경 변수와 **똑같은** 값         |

> ⚠️ **`localhost` / `127.0.0.1` 는 폰에서 접근 못 한다.** 반드시 인터넷에 배포된
> HTTPS 주소(`{{DEPLOY_URL}}`)를 넣어야 한다. Vercel 등에 배포한 뒤 그 주소를 쓴다.
> `{{INGEST_TOKEN}}` 은 `openssl rand -hex 32` 같은 걸로 길게 만들어 서버 환경 변수와
> 단축어 양쪽에 동일하게 넣는다.

## 1. 호출할 API

원문 저장 (A·B 단축어):

```
POST {{DEPLOY_URL}}/api/entries
Authorization: Bearer {{INGEST_TOKEN}}
Content-Type: application/json

{ "transcript": "방금 커피 한 잔 마셨어", "source": "voice" }
```

- `transcript` — 기록할 문장 (필수)
- `source` — 음성이면 `"voice"`, 타이핑이면 `"text"`
- `recorded_at` — **보내지 않는다.** 서버가 수신 시각(KST)으로 채운다. (단축어의 날짜
  출력은 ISO8601 이 아니라, 넣으면 오히려 서버 검증에서 400 이 난다. 말한 시점과 수신
  시점의 차이는 몇 초라 무시해도 된다.)
- 성공하면 `201`. 파싱은 서버가 **백그라운드로** 처리하므로 응답은 즉시 온다.

그날 원문 조회 (C 단축어):

```
GET {{DEPLOY_URL}}/api/entries?date=YYYY-MM-DD
Authorization: Bearer {{INGEST_TOKEN}}
```

- 그 날짜(KST)의 원문 목록을 돌려준다. GET 에도 **같은 Bearer 토큰**이 필요하다.

## 2. 단축어 A — 음성 기록

단축어 앱 → 우측 상단 **+** → **새 단축어**. 아래 액션을 위에서부터 차례로 추가한다.
(검색창에 액션 이름을 쳐서 찾는다.)

> ⚠️ **왜 "확인" 단계가 꼭 필요한가:** 서버는 원문(`raw_entries.transcript`)을 **불변**으로
> 저장한다 — `0002` 마이그레이션의 트리거가 UPDATE 를 막는다. 즉 **한 번 보내면 고칠 수
> 없다.** 받아쓰기(STT)가 틀렸으면 **전송 전에만** 바로잡을 수 있으므로, 아래 "입력 요청"
> 단계에서 확인·수정한 뒤 보낸다.

### 액션 1 — 텍스트 받아쓰기

- 액션 검색: **텍스트 받아쓰기** (Dictate Text)
- **언어**: 한국어
- **받아쓰기 종료**: "일시 정지 후" (말 멈추면 자동 종료) 권장

결과 변수: **`받아쓴 텍스트`(Dictated Text)**

### 액션 2 — 입력 요청 (전송 전 확인·수정)

- 액션 검색: **입력 요청** (Ask for Input)
- **입력 유형**: 텍스트
- **프롬프트**: `이대로 기록할까요? (오타는 지금 고치세요)`
- **기본 응답(Default Answer)**: 변수 **`받아쓴 텍스트`** 를 넣는다

받아쓴 문장이 미리 채워진 편집창이 뜬다. 틀린 데가 있으면 여기서 고치고 확인을 누른다.
결과 변수: **`제공된 입력`(Provided Input)**

### 액션 3 — URL의 콘텐츠 가져오기

- 액션 검색: **URL의 콘텐츠 가져오기** (Get Contents of URL)
- **URL**: `{{DEPLOY_URL}}/api/entries`
- 아래 화살표(▸)를 눌러 세부 설정을 편다:
  - **방식(Method)**: `POST`
  - **헤더(Headers)**: 2개 추가
    - `Authorization` = `Bearer {{INGEST_TOKEN}}` (Bearer, 공백 1칸, 토큰)
    - `Content-Type` = `application/json`
  - **요청 본문(Request Body)**: **JSON** 선택 후 필드 2개 추가
    - `transcript` (텍스트) → 값에 **반드시 `제공된 입력`(Ask for Input 결과)** 을 넣는다
    - `source` (텍스트) → `voice`

> 🚨 **가장 틀리기 쉬운 부분:** `transcript` 에 넣는 값은 **`받아쓴 텍스트`가 아니라
> `제공된 입력`이어야 한다.** `받아쓴 텍스트`를 넣으면 액션 2에서 고친 내용이 무시되고
> 원본 STT 결과가 그대로(그리고 되돌릴 수 없게) 저장된다. 변수를 꼭 확인하라.

본문은 `transcript` 와 `source` **두 개만** 넣는다. 날짜(`recorded_at`)는 넣지 않는다.

### 액션 4 — 알림 표시 (짧게 "기록됨")

하루에 여러 번 쓰므로 응답 JSON 을 통째로 보지 않는다. 성공은 **"기록됨"** 한 마디로,
실패일 때만 오류를 보여준다. **만약(If)** 액션으로 감싼다:

- **만약(If)**: 입력 = 변수 **`URL의 콘텐츠`(Contents of URL)**, 조건 = **"~을 포함"**, 값 = `error`
  - → **알림 표시**: 변수 **`URL의 콘텐츠`** (오류 원문 그대로 — §7 로 진단)
- **그 외(Otherwise)**
  - → **알림 표시**: `기록됨`
- **End If**

> 더 단순하게 하려면 If 없이 **알림 표시**에 텍스트 `기록됨` 만 넣어도 된다. 대신 실패해도
> "기록됨"이 떠서 놓칠 수 있으니, 그 경우 §4 의 "오늘 기록 확인"으로 실제 저장을 확인한다.

저장 후 단축어 이름을 알아보기 쉽게 바꾼다(예: **몸상태 기록**). 시리 문구는 §6 참고.

## 3. 단축어 B — 텍스트 기록

말하기 곤란한 상황(회의 중 등)에서 타이핑으로 기록한다.

### 액션 1 — 입력 요청

- 액션 검색: **입력 요청** (Ask for Input)
- **입력 유형**: 텍스트
- **프롬프트**: `무엇을 기록할까요?`
- 기본 응답은 비워 둔다.

결과 변수: **`제공된 입력`(Provided Input)**

### 액션 2 — URL의 콘텐츠 가져오기

§2 액션 3과 동일하되 두 가지만 다르다:

- **요청 본문(JSON)**:
  - `transcript` (텍스트) → **`제공된 입력`**
  - `source` (텍스트) → **`text`** ← 음성이 아니므로 `text`
- 나머지(URL, 방식 POST, 헤더 2개)는 A와 같다.

### 액션 3 — 알림 표시

§2 액션 4와 동일하게 성공은 **"기록됨"**, 실패는 오류 표시.

### 빠르게 실행 등록 (아무 단축어에나 적용 가능)

타이핑 기록은 화면을 보며 하므로 손이 닿는 곳에 걸어 둔다:

- **뒷면 두 번 탭**: 설정 → 손쉬운 사용 → 터치 → **뒷면 탭** → **이중 탭** → 이 단축어 지정.
- **잠금화면 위젯**: 잠금화면 길게 눌러 편집 → 위젯 추가 → **단축어** → 이 단축어 선택.
- **제어 센터**: 설정 → 제어 센터 → **제어 추가** → **단축어** → 이 단축어 선택.
  (또는 제어 센터에서 **+** → 단축어)
- **액션 버튼**(지원 기기): 설정 → 액션 버튼 → 단축어 → 이 단축어 지정.

## 4. 단축어 C — 오늘 기록 확인

> ⏳ **임시 확인 수단이다.** STEP 5 의 타임라인 웹(원문 + 파싱 결과 대조)이 나오면 이 단축어는
> 필요 없다. 그 전까지 "방금 보낸 게 저장됐나"를 폰에서 바로 확인하는 용도.

### 액션 1 — 현재 날짜

- 액션 검색: **현재 날짜** (Current Date)

### 액션 2 — 날짜 포맷 지정

- 액션 검색: **날짜 포맷 지정** (Format Date)
- **날짜 형식**: 사용자 지정(Custom)
- **형식 문자열**: `yyyy-MM-dd` (ISO8601 datetime 이 아니라 단순 날짜라 안전하다)

결과 변수: **`포맷 지정된 날짜`(Formatted Date)**

### 액션 3 — URL의 콘텐츠 가져오기

- **URL**: `{{DEPLOY_URL}}/api/entries?date=` + 변수 **`포맷 지정된 날짜`**
  (URL 칸에 텍스트로 치다가 그 자리에 변수를 삽입한다)
- **방식(Method)**: `GET`
- **헤더(Headers)**: `Authorization` = `Bearer {{INGEST_TOKEN}}` (본문 없음)

### 액션 4 — 빠른 응답 보기

- 액션 검색: **빠른 응답 보기** (Quick Look) — 입력에 변수 **`URL의 콘텐츠`**
- 그 날짜의 원문 목록이 JSON 으로 뜬다. (사람이 보기 좋은 화면은 STEP 5 에서.)

## 5. 애플워치에서 실행 (음성 기록)

1. 단축어 앱에서 **단축어 A** 를 열고 우측 상단 **(i)** / **세부사항**.
2. **"Apple Watch에 표시"(Show on Apple Watch)** 를 켠다.
3. 워치의 **단축어** 앱에서 실행되고, 받아쓰기·확인도 워치에서 된다. 별도 워치 앱은
   필요 없다. (워치 문자판 컴플리케이션이나 스마트 스택에 올려두면 더 빠르다.)

## 6. 시리 호출 문구 추천

단축어 이름이 곧 시리 호출 문구다. 짧고 발음이 또렷한 걸 추천:

- **"몸상태 기록"** (음성)
- **"컨디션 메모"** (텍스트)
- **"오늘 기록"** (확인)

시리에 대고 `"시리야, 몸상태 기록"` 이라고 하면 받아쓰기가 바로 시작된다. 문구가 다른
동작과 겹치면 인식이 흔들리니, 위처럼 고유한 2~3어절로 정한다.

## 7. 안 될 때 확인

알림을 §2·§3 대로 만들었다면 **성공은 "기록됨", 실패는 오류 JSON** 이 뜬다. 오류별로:

### `401` / `{"error":"unauthorized"}`

토큰 문제다. 원문은 저장되지 않았다.

- 헤더 이름이 정확히 `Authorization` 인지 (오타/대소문자 확인 — 값 스킴은 `Bearer`)
- 값이 `Bearer {{INGEST_TOKEN}}` 형식인지 (**`Bearer` + 공백 1칸 + 토큰**, 앞뒤 공백 금지)
- 단축어의 토큰과 서버 `INGEST_TOKEN` 환경 변수가 **완전히 동일**한지 (복붙 시 줄바꿈/공백 유입 주의)
- (C 단축어) GET 에도 Authorization 헤더를 넣었는지

### `500` / `{"error":"insert_failed", ...}`

서버가 원문을 저장하지 못했다. **원문이 저장되지 않았을 수 있으니 다시 시도**하고,
계속되면 서버 쪽을 확인한다.

- 서버 환경 변수: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `USER_ID` 설정 여부
- DB 마이그레이션(0001~0003) 적용 여부
- 배포 로그의 상세 오류(`detail` 필드)

### 아무 반응이 없거나 "연결할 수 없음"

- `{{DEPLOY_URL}}` 이 **배포된 HTTPS 주소**인지 (localhost 아님)
- 폰이 인터넷에 연결돼 있는지, 주소 오타 없는지 (`/api/entries` 까지 정확히)

### `400` / `{"error":"invalid_body"}`

본문에 불필요한 필드가 들어갔거나 형식이 안 맞을 때 나온다. 본문은 `transcript` 와
`source` **두 개만** 남긴다.

- `recorded_at` 같은 날짜 필드를 **넣지 않는다.** iOS 단축어의 날짜 출력은 ISO8601 이
  아니라 서버 검증에서 400 이 난다. 생략하면 서버가 수신 시각으로 채운다.
- `source` 값이 정확히 `voice`(A) / `text`(B) 인지.
- `transcript` 변수를 제대로 넣었는지 — 특히 **A는 `제공된 입력`**(받아쓴 텍스트 아님).
- 입력이 비어 있진 않은지(아무것도 없이 확인) — 다시 시도.

### `400` / `{"error":"invalid_json"}`

- 요청 본문이 **JSON** 형식으로 설정됐는지 (URL의 콘텐츠 가져오기 → 요청 본문 = JSON).

### 응답은 `201` 인데 파싱 결과가 안 보임

정상일 수 있다. **파싱은 백그라운드**라 원문 저장(201)과 별개로 잠시 뒤 처리된다.

- 원문(`raw_entries`)은 이미 저장됐다(단축어 C로 확인 가능). 파싱만 나중에
  `POST /api/parse` 로 재시도 가능.
- 서버에 `ANTHROPIC_API_KEY` 가 설정됐는지, 배포 로그에 `[entries] 백그라운드 파싱 실패`
  가 있는지 확인한다.
