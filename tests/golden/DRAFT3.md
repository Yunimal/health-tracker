# 골든셋 DRAFT3 — 운동 카테고리(case-019~024) "뽑혀야 할 것" 초안

새 카테고리 **activity(운동·신체활동)** 를 추가하기 위한 케이스다. 각 발화에 **무엇이
들어있는지 나열만** 했고, 파싱 결과(시각 확정 등)를 흉내내지 않는다. 판단이 갈리는
부분은 **애매한 점**에만 적고 확정하지 않았다 — 확정은 사람이 한다(2단계).

> ⚠️ **activity 의 payload 스키마·중복 규칙·"안 함" 처리 규칙은 아직 없다.** 아래 표의
> 카테고리 배정(activity)은 **제안**일 뿐이며, RULES 확정 전까지 미정이다. 각 case-XXX.json
> 의 `expected` 는 지금 비어 있고(빈 배열), 2단계에서 채운다.

## activity payload 초안 (미확정)

| 필드             | 타입                | 설명                        | 예                     |
| ---------------- | ------------------- | --------------------------- | ---------------------- |
| `name`           | 문자열 (필수)       | 운동 종류                   | "산책", "등산", "헬스" |
| `duration_min`   | 정수 또는 null      | 분 단위. 언급 없으면 null   | "30분" → 30            |
| `intensity_text` | 원문 표현 또는 null | 강도를 **말한 그대로** 보존 | "가볍게", "빡세게"     |
| `note`           | 문자열 또는 null    | 그 밖의 원문                | —                      |

## 확정된 설계 원칙 (사용자 지시)

1. **강도를 숫자(1~3 등)로 매기지 않는다.** 사람마다 기준이 달라 의미가 없다. 말한 표현을
   `intensity_text` 에 **그대로** 보존한다. (mood/energy 의 수치 척도와 다른 처리)
2. **근육통·뻐근함은 activity 가 아니다 → `unparsed` 유지.** activity 는 **행동**을 담는
   카테고리이고 근육통은 그 **결과인 증상**이다. 섞으면 "이번 주 운동 횟수" 집계가 오염된다.

- `종류`: `fact`(사실 이벤트) / `hypothesis`(추측) / `?`(귀속 자체가 미정)
- `카테고리`: activity / food / … / — (미정) / unparsed
- `시각`: 발화의 시간 단서 그대로 (occurred_at 확정 아님)

> 커버리지: 시간 명시(019) · 시간 없음(020) · 강도 표현(021) · 운동+식사 연접(022) ·
> 운동 후 증상=근육통 분리(023) · 운동 안 함(024, "안 함" 기록 여부 미정).

## case-019 — 시간 명시된 운동

> "오늘 아침에 동네 한 바퀴 30분 정도 걸었어."
> recorded_at: 2026-08-13 09:00 KST

| 종류 | 카테고리 | 내용            | 시각      | 애매한 점                                                    |
| ---- | -------- | --------------- | --------- | ------------------------------------------------------------ |
| fact | activity | 걷기/산책, 30분 | 오늘 아침 | name 을 "걷기" vs "산책" 무엇으로? "동네 한 바퀴"는 note 로? |

> `duration_min` = 30, `intensity_text` = null. "30분 정도" 의 "정도"를 근거로
> occurred_at_precision 을 part_of_day(아침)로 볼지, 시간 정밀도와 duration 은 별개인지 확인.

## case-020 — 시간 없는 운동

> "방금 산책 다녀왔어."
> recorded_at: 2026-08-13 19:30 KST

| 종류 | 카테고리 | 내용 | 시각 | 애매한 점                                               |
| ---- | -------- | ---- | ---- | ------------------------------------------------------- |
| fact | activity | 산책 | 방금 | `duration_min` = null (언급 없음). "방금"→exact 로 볼지 |

> 가장 단순한 활동 1건. duration/intensity 모두 null 일 때 confidence 감점 규칙이 필요한지
> (food 의 amount null 감점과 대칭인지) 미정.

## case-021 — 강도 표현이 있는 운동

> "저녁에 헬스장 가서 빡세게 운동하고 왔어."
> recorded_at: 2026-08-13 21:00 KST

| 종류 | 카테고리 | 내용                      | 시각 | 애매한 점                                                      |
| ---- | -------- | ------------------------- | ---- | -------------------------------------------------------------- |
| fact | activity | 헬스(운동), 강도 "빡세게" | 저녁 | name = "헬스" vs "운동"? `intensity_text` = "빡세게" 원문 보존 |

> `duration_min` = null, `intensity_text` = "빡세게". 강도를 절대 숫자화하지 않는다(원칙 1).
> "빡세게" 같은 표현이 confidence 에 영향 주지 않는지 확인.

## case-022 — 운동과 식사가 이어진 발화

> "점심에 김밥 먹고 바로 산책 다녀왔어."
> recorded_at: 2026-08-13 13:00 KST

| 종류 | 카테고리 | 내용             | 시각      | 애매한 점                                                     |
| ---- | -------- | ---------------- | --------- | ------------------------------------------------------------- |
| fact | food     | 김밥             | 점심      | 양 미언급(amount null)                                        |
| fact | activity | 산책             | 점심 직후 | `duration_min` = null. 산책 시각을 점심과 같게/직후로 볼지    |
| —    | —        | "먹고 바로 산책" | —         | **순서≠인과** → hypothesis 생성 금지(R1). 두 사실만 나와야 함 |

> 핵심 확인점: "먹고 바로 ~"는 시간 순서일 뿐 인과 주장이 아니다(기존 R1). food→activity
> 인과 hypothesis 를 만들면 오분류다. 사실 2건(food, activity)만 나오는 게 맞는지.

## case-023 — 운동 후 증상 (근육통이 unparsed 로 가는지)

> "어제 등산 다녀왔는데 오늘 허벅지가 뻐근하네."
> recorded_at: 2026-08-13 10:00 KST

| 종류 | 카테고리 | 내용                      | 시각 | 애매한 점                                                 |
| ---- | -------- | ------------------------- | ---- | --------------------------------------------------------- |
| fact | activity | 등산                      | 어제 | `duration_min`/`intensity` 미언급 → null                  |
| —    | unparsed | "허벅지가 뻐근함"(근육통) | 오늘 | **원칙 2**: 증상이므로 activity 아님 → unparsed 유지      |
| ?    | —        | "등산했더니 뻐근"         | —    | 등산→근육통 **인과를 hypothesis 로 볼지** 미정(아래 참고) |

> 핵심 확인점: 근육통은 **activity 에 흡수하지 않고 unparsed** 로 남는다(원칙 2). 다만
> 발화에 "~더니 ~하네" 같은 인과 뉘앙스가 있는지 — 있으면 hypothesis 로도 분리하는지가
> **case-005 와 직결**된다(하단 참조). 여기서는 확정하지 않는다.

## case-024 — 운동을 안 한 것에 대한 언급

> "오늘은 결국 운동을 못 했어."
> recorded_at: 2026-08-13 22:00 KST

| 종류 | 카테고리 | 내용           | 시각 | 애매한 점                                   |
| ---- | -------- | -------------- | ---- | ------------------------------------------- |
| ?    | activity | 운동 **안 함** | 오늘 | **"안 함"을 이벤트로 기록할지 미정** (아래) |

> 🔶 **미정 (사용자 지시로 확정 보류):** 결식(`skipped_meal`)처럼 "운동 안 함"을 사실로
> 남길지가 핵심 쟁점이다. 선택지:
>
> - (A) skipped 종류의 activity 이벤트로 기록 (결식 대칭). name 을 무엇으로? 일반 "운동"?
> - (B) 이벤트 없음 — "안 한 것"은 기록하지 않는다. 그럼 이 발화는 unparsed 혹은 무시.
> - (C) 계획/의지 표현(자책)으로 보고 카테고리 밖.
>
> 결식과의 차이: 결식은 끼니라는 **정해진 슬롯**이 있어 "안 먹음"이 정보가 된다. 운동은
> 정해진 슬롯이 없어 "안 함"의 정보량이 다르다 — 이 비대칭을 2단계에서 판단한다.

## case-005 영향 (2단계에서 함께 처리)

case-005 는 activity 도입으로 **expected 가 바뀐다.** 지금은 고치지 않고, 2단계에서 RULES
확정과 함께 처리한다. 바뀌어야 할 것만 적어 둔다.

> 원문: "지난 주말에 등산 갔다 와서 월요일까지 다리가 뻐근했어. 토요일 저녁엔 치킨도 시켜 먹었고."

**현재 expected (activity 없던 시절):**

- events: `food`(치킨) 1건
- hypotheses: "등산 갔다 와서 … 다리가 뻐근했어" (cause=등산, effect=다리 뻐근함) 1건
- unparsed: `["지난 주말에 등산 갔다 옴", "월요일까지 다리가 뻐근했어"]`

**activity 도입 후 바뀌어야 할 것:**

1. **`"지난 주말에 등산 갔다 옴"` 은 unparsed → `activity` 이벤트로 이동.**
   name="등산", duration/intensity=null, occurred_at=지난 주말(part_of_day 또는 date 정밀도).
   → **unparsed 에서 이 조각을 뺀다.**
2. **`"월요일까지 다리가 뻐근했어"` 는 근육통(증상)이므로 unparsed 에 그대로 유지**(원칙 2).
3. **hypothesis(등산→다리 뻐근함) 처리는 미정.** case-023 과 같은 쟁점이다:
   - 등산이 이제 activity **사실**로 잡히므로, "등산→뻐근함" 인과를 여전히 hypothesis 로
     둘지, 아니면 activity 사실 + unparsed 증상만 남기고 hypothesis 를 뺄지 판단 필요.
   - **이게 case-005 와 case-023 의 공통 확정 포인트다.** 둘을 같은 규칙으로 처리해야 한다.
4. 치킨(food) 이벤트는 그대로.

> 즉 case-005 는 (a) 등산 unparsed→activity 승격은 확실, (b) 근육통 unparsed 유지는 확실,
> (c) 인과 hypothesis 존치 여부만 case-023 과 묶어 미정. 2단계에서 RULES → v7 → 마이그레이션
> → 재파싱과 함께 expected 를 갱신한다.
