# 골든셋 DRAFT7 — focus / environment 카테고리 + v11 예정 항목 (case-051~060)

**결과 변수(focus)와 원인 후보(environment)를 하나씩 추가한다.** focus 는 "결과 ← 원인" 축의
새 결과이고, environment 는 새 원인 후보다. 함께 "## v11 예정"에 적어둔 두 항목(body_condition
`since_text`, body_condition 분리 few-shot)도 이번 버전에 넣는다.

각 발화에 **무엇이 들어있는지 나열만** 했고 파싱 결과(시각 확정·payload 전체)를 흉내내지
않는다. 판단이 갈리는 부분은 **애매한 점**에만 적고 확정하지 않았다 — 확정은 사람이 한다(3단계).

> ⚠️ v11 에는 **프롬프트 다이어트(few-shot 축소)를 넣지 않는다.** 그건 v12 에서 따로 한다.
> (둘을 섞으면 점수가 변했을 때 원인을 가릴 수 없다.)
>
> ⚠️ 각 case-XXX.json 의 `expected` 는 지금 비어 있고(빈 배열), 3단계에서 채운다.
> 카테고리는 현재 12개에서 **14개**로 늘어난다(focus, environment 추가).

## 추가할 카테고리 (사용자 지시 — 확정 스펙)

### focus — 집중 상태 (결과 변수)

| 필드    | 타입             | 설명                     |
| ------- | ---------------- | ------------------------ |
| `level` | 1~5 (필수)       | 아래 수치화 기준으로 고정 |
| `note`  | 문자열 또는 null | 그 밖의 원문             |

- **수치화 기준(R10 energy 와 같은 방식으로 규칙 고정):**
  1 아예 안 됨 / 2 산만함 / 3 보통 / 4 잘 됨 / 5 몰입
- **energy(기력)와 다른 축이다.** 피곤한데 집중되는 날이 있고 그 반대도 있다.
  "피곤한데 집중은 잘 됐어" → energy 1건 + focus 1건. (R4 의 energy/mood 분리와 같은 원칙)

### environment — 환경 요인 (원인 후보)

| 필드               | 타입             | 설명                                          |
| ------------------ | ---------------- | --------------------------------------------- |
| `kind`             | enum (필수)      | sleep / work / light_exposure / other         |
| `description_text` | 원문 표현 (필수) | "에어컨 켜고 잤어", "카페에서 작업했어"        |
| `note`             | 문자열 또는 null | 그 밖의 원문                                  |

- 예) "에어컨 켜고 잤어" → sleep · "카페에서 작업했어" → work · "밖에 나가서 햇빛 봤어" → light_exposure
- **환경은 상태도 행위도 아닌 맥락이다. activity(운동)와 혼동하지 마라.**
  "산책하면서 햇빛 봤어" → activity(산책) + environment(light_exposure) **2건.**

## 함께 처리할 v11 예정 항목 (RULES.md "## v11 예정")

1. **body_condition 에 `since_text` 필드 추가**(원문 표현, nullable) — 지속 상태의 발단 표현을
   보존한다. `occurred_at` 은 **관찰 시점(recorded_at)** 으로 한다(발단 시점으로 잡지 않는다).
   발단 날짜를 숫자로 계산하지 않는다 — "어제부터/요즘"의 정밀도가 제각각이라 원문만 남긴다.
2. **body_condition 분리 few-shot 추가** — 한 절 안의 두 감각("가렵고 따가운")을 분리하는
   예시가 없어 v10 골든에서 case-045 가 1건으로 합쳐졌다. v11 프롬프트에 예시를 넣는다.

## 반드시 지킬 원칙

1. **focus 는 결과 변수, environment 는 원인 후보다.** (분석 축이 다르다 — src/lib/analysis)
2. **focus 는 energy 와 다른 축.** 한 서술을 두 카테고리로 중복 생성하지 않되, 서로 다른
   서술(피곤함 + 집중됨)은 각각 뽑는다. (R4 와 같은 원칙)
3. **environment 는 activity 가 아니다.** 운동은 행위(activity), 환경은 맥락(environment).
4. **focus level 을 지어내지 않는다** — 위 수치화 기준(1~5)에 따라 고정한다.

> 커버리지: focus 잘 됨(051) · focus 안 됨(052) · energy↔focus 반대(053) · 수면시간+수면환경(054) ·
> 작업환경(055) · 햇빛(056) · 운동+햇빛 분리(057) · 물 섭취(058) · 술(059) · 지속상태 since_text(060).
> 058~060 은 새 카테고리가 아니라 **기존 기능이 실제로 되는지** 확인하는 케이스다(자주 쓰는
> 표현인데 골든에 없어 검증된 적이 없다).

## 3단계에서 확정할 열린 질문 (여기서 정하지 않음)

1. **focus 수치화 경계** — "완전 몰입"=5 / "잘 됐어"=4 / "산만"=2 / "하나도 안 됨"=1. 한 발화에
   여러 강도가 나올 때(051) 몇 건으로, 어느 값으로.
2. **environment enum 경계** — sleep/work/light_exposure/other 의 판별. "카페에서 작업"이
   work 인지(장소 vs 행위 맥락), "밖에 나감"만으로 light_exposure 인지.
3. **environment 와 sleep 의 관계(054)** — 수면 환경을 environment(sleep)로 별도 둘지, sleep
   이벤트 note 로 합칠지. (별도 권장 — 원인 후보로 쓰려면 독립 이벤트여야)
4. **since_text 범위** — "어제부터", "요즘", "며칠 됐어" 를 어디까지 원문으로 남길지. 발단
   날짜 숫자화는 하지 않음(확정).
5. **물/술의 payload** — 물의 amount, 술의 meal_type/alcohol 여부. 지금은 food(drink)로 두고
   별도 카테고리를 만들지 않는다(확정). 종류는 name 에 보존.
6. **confidence(R6)** — focus/environment 에 amount 개념 없음 → precision 페널티만
   (energy/activity 처럼). R6 에 두 카테고리 명시.
7. **스키마/마이그레이션** — events.category CHECK 를 14개로(0011). schema.ts(FocusPayload/
   EnvironmentPayload + body_condition 에 since_text)·index.ts zod·v11 프롬프트·format.ts·
   RULES(R25 focus / R26 environment + R23 since_text 보강) 갱신. 순서: RULES → 프롬프트 →
   골든 expected → 마이그레이션 먼저 → 배치 재파싱. (CLAUDE.md 원칙 2/5)

> 확정 후: RULES(R25/R26 + R23 since_text) → v11 프롬프트(few-shot 축소 없이, body_condition 분리
> 예시 추가) → case-051~060 expected 채움 → 0011 마이그레이션 → 배치 재파싱 → test:golden.
